# 04: Voice & language selection

**What to build:** Voice and Rate control. `--voice`, `--rate` and `--language` flags; by default the tool auto-picks the best available Voice for the Book's language (premium > enhanced > default quality). Rate is Apple's native 0–1 utterance scale, passed through unchanged.

**Blocked by:** 01 (Skeleton — one-chapter Book to playable M4B)

**Status:** resolved

- [x] With no flags, the Voice used is the best-quality installed voice for the Book's OPF language, and the choice is visible in the progress/summary output
- [x] `--voice <name>` accepts a voice identifier or display name as listed by `say -v ?`; an unknown name fails with exit 1 and a readable message
- [x] `--rate` accepts 0.0–1.0 (default 0.5) and is passed straight through to the utterance; out-of-range values fail with exit 1
- [x] `--language` overrides the Book's language for voice selection
- [x] A language with no installed Voice fails with exit 1 and a readable error naming the language
- [x] Changing voice or rate on the same fixture audibly changes the output (manual check — objective stand-ins pinned in tests; human listen recommended)

- 2026-09-11 (agent): Implemented. New modules: `Voice` (the `Voice`/`VoiceQuality` value types; `VoiceSelection` = highest quality for the language — exact BCP-47 tag case-insensitive, then same primary subtag, e.g. "pt-BR" accepts a "pt-PT" voice — premium > enhanced > default with ties to catalog order; `named` = identifier or display name, exact beats case-insensitive wherever it sits in the catalog; `VoiceCatalog` maps `AVSpeechSynthesisVoice.speechVoices()`), and `CLIOptions` (`--voice`/`--rate`/`--language`; Rate 0.0–1.0 default 0.5 enforced at parse; unknown flags — including `-o`, `--force`, `--keep-scratch`, which belong to ticket 06 — fail with usage, exit 1). CLI wiring: an explicit `--voice` is resolved before any work (fast fail, no Scratch side effects); the auto case resolves after load so the Book's OPF language applies, `--language` overrides it; the choice is reported on stderr before the per-chapter progress as `Voice: <name> (<quality>, <language>) · Rate: <rate>`; `utterance.voice`/`utterance.rate = Float(rate)` pass through unchanged. Research (measured on this machine): the first `say -v ?` column is `AVSpeechSynthesisVoice.name` (e.g. "Bad News"), the engine's `identifier` is the long `com.apple.*` string — `named` matches both; every installed voice here reports quality 1 (enhanced) with no premium tier, which is why the quality ordering is pinned with synthetic voices at the pure seam; `AVSpeechSynthesisVoice(language: "xx-XX")` is nil, so the catalog check (not AVFoundation) is what makes "no voice for language" deterministic; the 0–1 Rate scale is non-linear in duration (the 21-word fixture: 7.0 s at 0.5, 1.97 s at 0.9).
