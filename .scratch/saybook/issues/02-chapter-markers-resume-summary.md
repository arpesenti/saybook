# 02: Chapter Markers, resume & summary

**What to build:** A multi-Chapter Book produces one Audiobook with a titled Chapter Marker at each Chapter start; re-running the same command resumes from existing Scratch (Chapters whose CAF already exists are not re-synthesised); a final summary is printed. Marker offsets come from known per-chapter frame counts against the track timescale — computed, not parsed.

**Blocked by:** 01 (Skeleton — one-chapter Book to playable M4B)

**Status:** resolved

- [x] A 3-chapter fixture produces one M4B with exactly 3 Chapter Markers (`chpl`), each carrying the Chapter's title
- [x] Marker offsets land at the true Chapter boundaries (within one AAC frame), verified by a test that parses the `chpl` and compares against known PCM lengths
- [x] Chapter titles fall back: largest heading in the document → filename (EPUB3 nav titles arrive in ticket 03)
- [x] Kill the run mid-way, re-run: existing Chapters are skipped, no re-synthesis, and the final Audiobook is complete and correct
- [x] Final summary reports: chapter count, skipped count, total duration, output size and path
- [x] Scratch is deleted on success and kept on failure

## Comments

- 2026-09-11 (agent): Implemented. New modules: `ChapterMarkers` (offsets → `chpl` box → byte-level insertion into the encoded M4A → `parseChpl` reader) and `Scratch` (per-run directory keyed on the input's path|size|mtime, so re-runs land on the same Scratch and find finished Chapter CAFs; layout helpers `chaptersDirectory`/`chapterCAFURL`). `Synthesis.render` now publishes atomically (`*.caf.partial` → rename on success), so a killed run never leaves a partial CAF at a chapter's final name; resume is then just "CAF exists at final name = chapter finished". `CLI` gained: resume skip with `⏭ n/N · title · m:ss (cached)` lines, Empty-Chapter skip (`– n/N · title · (no text)`, no audio, no marker, counted in the summary as `Skipped: k (no text)`), and the final summary line `Chapters: N · Skipped: k (no text) · Duration: m:ss · Size: X · Path: …` (scratch deleted on success, kept with its path on failure). Fixture grew: `multi-chapter.epub` (4 spine docs: h1 "Chapter One" 13 words, h2 "Chapter Two" 184 words, no-heading 248 words → title "ch3", and an empty doc → "ch4") exercises the title fallback, the empty-chapter path, and gives the kill test a wide window. Two research results drive the design, both measured on this machine: (1) `prototype/aac-boundary-probe.swift` — the export pipeline's edit list trims AAC priming exactly (decoded frames == input frames, 0 leading silence, tone→silence delta 0), so cumulative PCM frame counts ARE the true chapter boundaries and need no priming compensation; (2) the `chpl` byte layout follows FFmpeg's mov muxer (the format real Apple M4Bs carry): `moov/udta/chpl`, version 1, i64 BE start times in 100 ns units, u8 title-length + raw UTF-8 titles. Offsets are converted from track-timescale samples (22 050) to 100 ns by exact integer math. Verified independently: ffprobe reads back the chapters (titles + start times matching known PCM lengths to <1 ms), `file` reports the M4B brand, ffmpeg full decode clean. Tests: `ChapterMarkersTests` (offset math, exact byte layout, insertion incl. merge-into-existing-udta, round-trip parse, ffprobe cross-check), `CLITests` (4-chapter markers/summary, deterministic resume with pre-seeded CAFs and tone/silence/tone content proof, SIGKILL mid-run then resume).
- 2026-09-11 (agent): Two-axis code review ran (Standards: no documented repo standards, Fowler baseline; Spec: this ticket + spec.md). Findings addressed in the follow-up commit: (1) `chpl` now merges into the moov's existing trailing `udta` (AVAssetExportSession writes one with encoder metadata) instead of appending a second `udta` — matching the single-udta-per-moov layout of Apple's own M4Bs, so readers that consult only the first `udta` still find the markers (new `testInsertMergesIntoExistingUdta` pins the layout; the real-file walk shows `udta` = `meta` + `chpl`); (2) the empty-chapter path was previously untested — the fixture's 4th empty doc now drives it end-to-end (progress line, `Skipped: 1 (no text)` summary annotation, no marker); (3) chapter-CAF naming scheme de-duplicated into `Scratch.chaptersDirectory`/`chapterCAFURL` (CLI and tests share it); (4) tests' hard-coded 22 050 now reference `Synthesis.sampleRate`; (5) opaque test helpers `u32b`/`u64b` renamed `bigEndianU32`/`bigEndianU64`.
