# 06: Error paths, safety & signals

**What to build:** The tool's failure behaviour, matching the spec: `--force` output clobber, the 0/1/2 exit-code contract, DRM detection, empty-Book and empty-Chapter handling, non-XHTML Spine items, and graceful SIGINT handling.

**Blocked by:** 02 (Chapter Markers, resume & summary), 05 (Block-level text with natural pauses)

**Status:** resolved

- [x] Without `--force`, an existing output file is refused (exit 1); with `--force` it is replaced
- [x] Exit codes: 0 on success; 1 for input/user errors (unreadable or invalid EPUB, DRM-encrypted content, no readable Chapters, no Voice for the language, output exists); 2 for internal errors
- [x] An EPUB with an encrypted OPF or encrypted content items fails cleanly with a readable DRM error — no crash, no half-written output file
- [x] A Book with no readable Chapters fails with exit 1 and a message
- [x] A Chapter that yields no text produces no audio and no Chapter Marker, and is listed in the summary as `skipped (no text)`
- [x] Non-XHTML Spine items (video, images, other media) are skipped without failing the run
- [x] SIGINT stops the run after the current unit of work, keeps Scratch, prints progress so far, and exits cleanly (resume by re-running)
- [x] Each failure mode is covered by a test that asserts the exit code and the message (no synthesis needed — exercise via fixtures and stubs)

- 2026-09-11 (agent): Implemented (commit "Implement #06"). CLI surface: `CLIOptions` gains `outputPath`/`force`/`keepScratch` — `-o OUT.m4b` (no long alias: the spec names only `-o`), `--force`, `--keep-scratch`. `saybookMain` resolves the output (`-o`, else `<InputBase>.m4b` beside the input) and pre-validates it before any work: a missing `-o` parent directory or an output path that is a directory is a fast exit 1 (user error, no Scratch side effects); an existing output file is refused unless `--force` (exit 1, unchanged from #01). The final M4B is now published via `AtomicPublish` (`.partial` + rename beside the output), so a `--force` replacement killed mid-write cannot leave a half-written file at the output path; `--keep-scratch` skips the on-success Scratch deletion and reports the path. DRM: `Epub.load` reads `META-INF/encryption.xml` (root-relative `URI` attributes resolved against the unpacked archive) before parsing the OPF — an encrypted OPF fails first (its bytes never reach the OPF parser), and *any* manifest item listed there or declared with an `x-enc+xml` media type is a clean `EpubError.drmEncrypted(uri:)` → `error: DRM-protected EPUB: "…" is encrypted (only non-DRM books are supported)`, exit 1, no output, Scratch kept (failure keeps Scratch, per #02). The spec's constraint is "encrypted content → clean error", so the check is manifest-wide, not just Spine: a Book that encrypts even its cover image is not a non-DRM Book (a real DRM Book always encrypts the OPF or content, so real DRM books fail either way). No readable Chapters: `EpubError.noReadableChapters` (a well-formed EPUB whose Spine holds zero readable documents, distinct from `notAValidEpub`) → `error: No readable chapters in <input>`, exit 1; a Book whose Chapters all yield no text hits the pre-existing synthesis-stage `SaybookError` ("No readable chapters in <Book title>"), also exit 1 — the all-empty case produces no audio and no markers, so a zero-length Audiobook is refused. Non-XHTML Spine items were already skipped by the html-media-type filter; now pinned by the `media-spine.epub` fixture whose `intro.mp4`/`art.png` are deliberately absent from the archive (reading either would fail the run). SIGINT: new `Signals` module — a C-convention handler that only sets a word-sized flag (signal context); a second SIGINT restores `SIG_DFL` and re-raises so a stuck run can always be force-killed. The run checks the flag at unit boundaries (after each Block render, at each Chapter boundary, before encoding) and throws `RunInterrupted` → `note: interrupted — stopped after N of M chapters` + `note: scratch kept for resume: <path>`, exit 1 (the spec leaves the interruption code unspecified; 1 = user-initiated stop, 2 stays for internal errors). Per-Chapter progress lines are the progress-so-far report; Scratch is kept, so re-running resumes (existing Chapters skip as cached). Seams tested: (1) `CLIOptions.parse` unit tests (new flags, missing value, unknown `--output`); (2) `Epub.load` unit tests against the new fixtures plus in-memory mini-EPUBs: `drm-content.epub` (encryption.xml + x-enc media type), `drm-opf.epub` (encrypted OPF), encryption.xml-only signal, x-enc-media-type-only signal, a non-Spine encrypted item (`testLoadFailsWhenNonSpineItemIsEncrypted`), `no-readable-chapters.epub` (Spine of only `linear="no"` documents), an empty Spine, and `media-spine.epub` (two chapters spoken in Spine order, media never read); (3) e2e via the real binary (each asserts exit code + message): DRM ×2, no-readable-chapters, all-empty Book (`all-empty-book.epub`, image-only chapter — no synthesis), media spine (exit 0, two ✓ lines, two markers), `--force` replacement (sentinel gone, M4B brand intact), `-o` custom path (default path not created), `-o` missing parent dir (exit 1, no Scratch created), directory-as-output (exit 1 with and without `--force`, directory untouched, no Scratch), exit 2 (output directory chmod 0o555 → internal write failure; skips under root, where permissions are bypassed), `--keep-scratch` (output written, Scratch + Chapter CAF survive), and SIGINT (waits for the `✓ 1/4` line before signaling — no blind sleep; asserts a clean exit 1, not a signal death, the `note: interrupted` line, progress so far, Scratch kept, no output, surviving CAFs a prefix, and a resuming re-run that caches the survivors and completes with 3 correct markers). New test helpers: `zipTree`/`writeTreeFile` (TestSupport) for in-memory EPUBs; the SIGINT test's stderr collector reads one byte at a time — on this SDK `FileHandle.read(upToCount: n)` blocks until n bytes *or* EOF, not until any data (verified with a probe: a 4096-byte reader on a ~300-byte child only woke at child exit, which made an earlier test version kill an already-dead pid — ESRCH). Full suite: 135 tests, 0 failures, ~28 s (under #07's 2-minute budget), non-root, zero network.
