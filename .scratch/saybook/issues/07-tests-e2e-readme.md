- 2026-09-11 (agent): The `ftyp` round-trip item (item 2) caught a real P0: **release-built M4Bs were undecodable.** `Brand.appendU32` iterated the `withUnsafeBytes` buffer *after* the closure returned (`data.append(contentsOf: withUnsafeBytes(of:) { $0 })`) — the pointer is only valid inside the closure, so under `-O` the append read a reused stack slot. Both 4-byte fields it wrote (ftyp size, minor version) came out as stack garbage (e.g. `D8 BE 3A 6F` for the size), the brand fields (appended via `contentsOf:`) were fine, and the file's total size was unchanged — so every byte-level assertion that only looked at the brand range, and every test that built its expectation with the *same* broken helper (the file-local `appendU32` in `BrandTests` had the identical defect), held by accident. It was invisible in `-Onone` (dead slot still holds the value), invisible to the unit suite (135 green in debug), invisible to the CLI e2e tests (they run the **debug** binary and only assert the brand bytes at `8..<12`/`12..<24`), and visible only by running the real release binary on a real Book: `saybook` failed at the `moov` step with `noMoovBox` because the garbage size field made the box walk stop before `moov`. Fix: materialise the bytes inside the closure (`withUnsafeBytes(of:) { Array($0) }`), with an in-code comment on the lifetime rule. New tests: (a) the exact 28-byte patched `ftyp` asserted against an **independent byte literal** (deliberately not built with any shared helper — a shared builder re-introduces the masking defect), and (b) the round trip the item names: real `AVAssetExportSession` M4A → `patchFTyp` → written to disk → still decodes (`AVAudioFile` opens it and reports ~full decoded length, format 22.05 kHz mono) and reports the M4B brand (own `ftyp` intact including the size field, plus `afinfo`'s `m4bf` file type ID). Both are red under `swift test -c release` pre-fix (the decode test: `ExtAudioFileOpenURL` refuses the file) and green after. Consequence: the suite is now verified green in **both** configurations — the shipping config is release, and this bug class is only visible there; that fact is in the README.
