# 03: Book metadata, cover & navigation

**What to build:** The Audiobook carries the Book's identity: title, author and album in `ilst` metadata boxes plus the cover image as a `covr` box, all degrading gracefully (a failed box write keeps the file with a warning). Chapter titles are taken from the EPUB3 navigation document when present, with the ticket-02 fallbacks otherwise. Navigation, cover and titlepage Spine documents are never spoken.

**Blocked by:** 01 (Skeleton — one-chapter Book to playable M4B)

**Status:** resolved

- [x] `afinfo`/`mdls` on the output show title = Book title, artist = author, album = Book title
- [x] A missing author degrades to a sensible placeholder (e.g. "Unknown") rather than an empty box
- [x] When the OPF declares a cover image, a `covr` box is present and the image is extractable from the file
- [x] When the OPF declares no cover, no `covr` box is written and nothing crashes
- [x] An EPUB3 Book's Chapter Marker titles match its navigation entries; an EPUB2 Book (no nav) uses the largest-heading → filename fallback
- [x] A fixture whose Spine contains a TOC/navigation page and a cover page speaks neither of them
- [x] A deliberately broken cover image (bad reference) degrades gracefully: file still written, warning emitted

- 2026-09-11 (agent): Implemented. New modules: `Mp4` (the shared box-layout primitives — `topLevelBoxes` walk with 64-bit sizes, `trailingMoov`/`trailingUdta` (the append-at-end invariants), `appendToMoovUdta` — extracted out of `ChapterMarkers`, which now delegates to it and keeps its public API/error vocabulary) and `Metadata` (`BookMetadata` identity → `moov/udta/meta { hdlr, ilst { ©nam, ©ART, ©alb, covr } }` writer, plus `parseIlst`/`parseCovr` readers for verification). `Epub` gained: `Book.cover` (`absent` / `data` / `missing(reference:)`), cover-image resolution (EPUB3 `properties="cover"` on manifest item or Spine itemref, EPUB2 `<meta name="cover"/>`), Chapter titles from the EPUB3 navigation document (anchor `href`s resolved against the nav doc, fragment dropped, keyed by the Spine document's standardized path; missing/unreadable nav degrades to the ticket-02 fallback), and never-spoken Spine exclusion (`linear="no"` or `nav`/`cover`/`doc-cover`/`doc-titlepage` properties on itemref or item). `CLI` now inserts the identity after the brand patch and before the Chapter Markers, degrading gracefully: a failed box write keeps the file with a `warning:` line, and a broken cover reference warns `cover image "…" declared but not found; no cover written`. New fixtures: `nav-cover.epub` (EPUB3 with nav doc, TOC page + titlepage `linear="no"`, a cover page `properties="doc-cover"` without `linear="no"`, and a declared PNG cover), `missing-cover.epub` (declared cover, file absent), `no-author.epub` (no `dc:creator`), `epub2.epub` (version 2.0, no nav — heading fallback). Research (measured on this machine): the layout is `moov/udta/meta { hdlr, ilst }` — FFmpeg's mov muxer writes exactly this, and it is the layout `mdls` (Spotlight's Audio.mdimporter) reads title/artist/album from; a bare `udta/ilst` without the `meta` wrapper is what `mdls` ignores (ffprobe reads both). Each tag wraps one `data` box whose type lives in the **flags** (version=0, flags=type; locale=0) — type 1 = UTF-8, 13/14 = JPEG/PNG for `covr` (initial probe with a separate 4-byte type field produced empty values in ffprobe, which is how the flags layout was pinned). `covr` sits inside `ilst` (the conventional M4B placement per the cover-art-locator literature / mutagen), typed 13/14 by magic bytes. AVAssetExportSession already writes `udta/meta { hdlr, ilst { ---- } }`, so insertion merges the tags into that existing `ilst` (single `ilst` per `meta`), guarded so the grown ranges only stretch over the new bytes (`meta` must be `udta`'s last child, `ilst` must be `meta`'s last child; otherwise a fresh `meta` is appended — pinned by `testInsertAppendsFreshMetaWhenEncoderMetaIsNotLastInUdta`). Verified independently: ffprobe reads back title/artist/album on a real encoded M4B (`testFFProbeReadsInsertedMetadata`), `mdls`/`mdimport -t` on the real output shows `kMDItemTitle`/`kMDItemAuthors`/`kMDItemAlbum`, and a python box walk extracts the `covr` bytes byte-identical to the fixture PNG (`file` confirms a valid PNG). afinfo shows the audio format but not the tags (mdls carries the identity check).
- 2026-09-11 (agent): Two-axis code review ran (Standards: no documented repo standards, Fowler baseline; Spec: this ticket + spec.md) — both axes OK with notes; all actionable findings addressed in the change set: (1) the Spec P1 gap — the fixture now exercises a cover *page* document (not just a cover *image*): `nav-cover.epub` carries a `cover.xhtml` with `properties="doc-cover"` and deliberately **without** `linear="no"`, so the property rule alone is proven to exclude it; (2) `Mp4.topLevelBoxes` now bounds-checks the 8-byte extended-size read (a truncated 64-bit-size box stopped the walk trapping; pinned by `testBoxWalkStopsAtTruncated64BitSize`); (3) the `meta`/`ilst` merge invariants above (unguarded, the grown ranges would have swallowed trailing siblings such as `chpl`); (4) the trailing-moov/udta invariants are shared (`Mp4.trailingMoov`/`trailingUdta`, used by both `Mp4.appendToMoovUdta` and `Metadata.insert`); (5) the `ilst` tag 4CCs are defined once as byte arrays (`Tag4CC`) and the parser compares against the iso-latin1 spelling derived from the same bytes (0xA9 ≠ UTF-8 "©", which is why the writer must not use `"©nam".utf8`); (6) `BookMetadata(book:)` moves the Book→identity mapping off the CLI (Feature Envy), with `CoverImage.imageData`; (7) `Synthesis.trackTimescale` replaces the `Int(Synthesis.sampleRate)` casts at all five call sites; (8) `Metadata.box(for:)` tightened to internal (no consumer outside the module) and `imageType` renamed `dataBoxType` (it returns the `data` box's type code).
