# Second speech engine: the private Siri engine, opt-in

saybook offers `--engine siri`, which renders Chapter audio with Apple's **private** Siri speech engine instead of the public `AVSpeechSynthesizer` of ADR-0001. It is reached by `dlopen`ing `/System/Library/PrivateFrameworks/SiriTTS.framework` and calling the C++ class `TTSSynthesizer` through a thin C bridge (`Sources/SiriTTSBridge`), because no public API exposes it. The default engine stays `apple`; the Siri engine is never chosen implicitly, and the run's progress header names it (`Engine: siri (private Siri engine — offline, unsupported)`).

Verified on macOS 27.0 (26A428) / M4, 2026-09-19; see `.scratch/saybook/research/private-api-speech-synthesis.md` for the probe trail.

## Considered options

- **Public API**: does not exist. `AVSpeechSynthesis.h`'s newest availability marker is `macos(14.0)`; `FoundationModels.swiftinterface` contains no audio or speech type at all; the 184 voice identifiers reachable privately via `TTSSpeechManager` are the same set `say -v ?` lists, and `-_speechVoiceForIdentifier:language:footprint:` silently returns the public voice for any identifier asked for. Nothing to call.
- **AFM 3 expressive speech**: the third-generation Apple Foundation Models do generate speech (the 20 B sparse Core Advanced model drives a DiT detokenizer), but there is no API — public or otherwise documented — for audio out, and this Mac carries no expressive-voice assets (`ProsodyTransferAssetPath`/`OrchestratorAssetPath` empty). The only legitimate AFM 3 use here is generating SSML for the engine that already exists.
- **The `com.apple.sirittsd` XPC service** (`SiriTTSDaemonSession`, `synthesizeWithRequest:didFinish:`): closed to an unentitled CLI — `NSCocoaErrorDomain Code=4097 "connection to service named com.apple.sirittsd"`, distinct from the `INVALIDATED` a bogus service name produces. Rejected.
- **The in-process framework**: open. `TTSSynthesizer` has 183 exported symbols; with the voice bundle's `AssetData` directory passed to `initialize`, `ready_for_synthesis()` returns 1 and `synthesize_text_sync` returned 263 640 bytes of PCM for one sentence. Chosen.
- **Third-party or cloud TTS**: rules itself out — saybook is offline with no third-party runtime dependencies (ADR-0001).

## Decision

Route the Siri engine behind the same `Synthesis`-shaped seam as the public engine (`SpeechEngine.render(text:voice:rate:to:)`), so `CLI`, `Assemble`, `Encode` and Chapter Markers stay engine-neutral, and keep every private-API symbol reference inside `Sources/SiriTTSBridge`, which exposes only `saybook_siri_probe`, `saybook_siri_synthesize` and `saybook_siri_free`.

## Consequences

- **Output format is ours to know, not to ask about.** The engine emits 48 kHz mono signed 16-bit little-endian PCM (`sample_rate_out: 48000` in the voice bundle's `gryphon.cfg`; `+[SiriTTSNeuralUtils currentSampleRate:]` reports 24 000 for the pre-vocoder stage). `SiriSynthesis` resamples into the package's existing contract — 22.05 kHz mono Float32 CAF — with `AVAudioConverter` at high quality, and refuses a render whose frame count disagrees with the expected one, because Chapter Marker offsets are computed from frame counts. Cross-check: the multi-chapter fixture measures 135.7 s through the Siri engine and 128.0 s through the public one — 6% apart, where a sample-rate mistake would be off by a factor of two.
- **Cached Chapters are tagged with the engine.** The Scratch options marker gained an `engine=` field, so audio rendered by one engine is never reused as resume state for the other.
- **No rate control.** The engine speaks at the voice's own rate, so `--rate` with `--engine siri` is refused rather than silently ignored; a book cannot be assembled at a rate no option produced.
- **Voices are delivered by macOS, not by us.** Siri voice bundles live under `/System/Library/AssetsV2/com_apple_MobileAsset_UAF_Siri_TextToSpeech`; a Mac may have none, and there is no `say -v ?` for them, so `--engine siri`'s errors name the installed bundles (here: one, `Martha`, `en-GB`, `fastspeech2_mil_base`).
- **Any OS update can break it.** The bridge resolves mangled C++ symbols (`__ZN14TTSSynthesizer20synthesize_text_syncE…`) at runtime, with the Mach-O leading underscore stripped. A renamed or re-mangled symbol, or `ready_for_synthesis()` returning false, becomes a readable user error and exit 1 with no output file — the run never falls back to another engine on its own, because a book in an unrequested voice is worse than a failed run, and never writes a partial Chapter.
- **The engine must be muted.** `Diagnostics::log` writes to stdout/stderr from the calling thread regardless of `set_log_level`: one 6-second Chapter produced 153 873 bytes. That is fatal when stderr is a pipe nobody drains — the 64 KB buffer fills and `synthesize_text_sync` blocks in `write` forever. The bridge points both descriptors at `/dev/null` across every engine call and restores them afterwards; `SAYBOOK_SIRI_DIAGNOSTICS=1` keeps the chatter for debugging.
- **A loaded voice is kept for the process's life.** Loading a bundle (FastSpeech2 + WaveRNN + G2P models) costs hundreds of MB and seconds, so one engine per voice asset is cached; the object's true size is unknown, so it is allocated with a 128 KB over-reservation and deliberately never freed. `initialize`'s third argument is a persistent-module name, not a locale — passing `"en-GB"` aborts with `FrontendModuleBroker: Unknown module 'en-GB'`, so an empty string is passed.
- **A Block renders in one blocking call.** `synthesize_text_sync` returns the whole utterance rather than streaming, so it needs no main-runloop pumping (unlike `write()` in ADR-0001) — and it also blocks the main thread for the duration. Cooperative SIGINT still works (the handler only sets a flag) but is noticed at the next Block boundary, so `Ctrl-C` costs at most one Block of work.
- **It is private API.** Fine for a personal command-line tool; this makes the binary ineligible for App Store distribution and unfit to ship to anyone else's machine as a supported product. The default engine remains the public one for exactly that reason.
